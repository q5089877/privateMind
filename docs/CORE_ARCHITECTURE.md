# Mind Harbor 核心架構準則

> 說出來 → 看一看 → 收回來 → 放下去。  
> 時間留下痕跡；下次回來，不必重新開始。

> **陪你把卡在心裡的事說清一點，再安心地放下。**

本文件是思緒停靠的產品與程式共同準則。任何新功能、AI prompt、資料欄位或 UI 改動，都必須先符合這份準則；若現有程式與本文衝突，應以本文為目標修正，而不是延續舊行為。

思緒停靠不是待辦工具、筆記分類器或心理治療產品。它讓人留下還沒有答案的事；AI 能陪人真的談、指出有根據的新角度，並在時間累積後看見一件事如何走到今天，最後允許事情暫時沒有結論。

產品不是用「少說一點」與其他 AI journal 區隔，而是用洞見的證據區隔：每一個關於過去的觀察，都必須能回指使用者自己的原文與時間。AI 可以有觀點，但不能把猜測包裝成事實。

## 一、產品循環

### 1. 留下

首頁提供零負擔的生理與思緒入口：

- **Level 0 🤍 全螢幕沉降注水平靜心跳（純生理／感官阻絕出口）**：針對急性大腦超載、心率緊繃或連字都不想面對的狀態。頂部常設心跳按鈕（44px），提供雙軌體感互動：
  - **短按輕點（Tap / 戳戳樂模式）**：提供即時俐落的 55ms 觸覺脈衝，供使用者快速戳擊宣洩多餘精力，次數即時累加。
  - **長按定心（Hold / 沉澱轉化期）**：按住超過 240ms 門檻，深邃潮水自螢幕底端湧升淹沒雜訊，伴隨每分鐘約 60 次（~60 BPM，雙脈衝 lub-dub）的平靜生理心跳震動與雙心音共振。
  - **心流維持（Sustain / 滿載共振）**：水位達 100%（約 2.5 秒）後不自動中斷，持續維持穩定心跳震動與微幅呼吸光環，直到使用者放開手指。
  - **釋放著陸（Release）**：移開手指時安靜停止震動並平滑退潮，記一次沉澱定錨。全程不強迫輸入文字，不帶情緒評價。
  - **中性使用紀錄**：短按放開後記一筆 `tap`；長按真正跨過門檻並放開後記一筆 `hold`。首頁只顯示本地日期的「今天輕點幾次／定錨幾次」，不稱為焦慮次數、不評分、不建立等級。
- **Level 1 四態草稿膠囊（極低阻抗入口）**：針對腦內混亂但不知從何說起的狀態，提供四個口語膠囊（「腦袋太吵」、「心裡很悶」、「事情卡住」、「先留著」），點擊後自動填入可編輯草稿，降低啟動門檻。
- **直接輸入**：自由輸入依然是核心主幹。使用者不必選主題、命名、分類或決定這是不是某件事的後續。

每一次輸入都先成為獨立的 `Moment`：它保存使用者的原文與時間，永遠不被 AI 改寫、摘要覆蓋或移動到別的位置。

### 2. 展開

一個 Moment 會開始一個 `HarborSession`。如果使用者想繼續說，新的使用者回合與 AI 回應都保留在同一個 session 裡，形成可見的 `ConversationTurn` 對話。

使用者在首頁明確選擇「接著說」並進入 `CHAT` 後，`HarborFlowEngine` 必須立即為起始 Moment 請求一次 `Present Companion` 回應；不要求使用者先補第二句，也不得由 `ChatScreen` 直接呼叫 AI。若該 Moment 已有有效的 `immediateReply` 或 session 已有對應的 assistant turn，則直接呈現既有回應，不重複請求。

AI 作為客觀的「外掛前額葉」，以語義手術刀拆解句子：
- **客觀張力**：直接點出原句中客觀存在的兩股拉扯（如：想快點做好 vs 現實需要時間；身體疲憊 vs 大腦預演）。
- **物理邊界**：切開「已經發生的客觀事實」與「尚未發生的腦內預演」，嚴禁使用心理學術語。
- **降維支點**：留下一個貼著原文的中性陳述；反思問題只允許出現在使用者主動開啟的 Explore。

### 3. 收束與心智封裝（Zeigarnik Box）

「停靠」不是一個送出按鈕，而是物理感的心智封箱。使用者選擇「今天先到這裡」後，系統請 AI 產生一份 `SessionClosure`（心智封裝憑證）草稿：

- **【今日結算】（這次先帶走）**：15 到 80 字，整理對話中已經說明白的客觀事實。
- **【目前缺少的資料】**：18 到 36 字，只陳述目前無法驗證的事實或不可控的外部變數；不得使用比喻、安慰、作息假設或心態總結。
- **接續錨點**：下次若要接著談，可以從哪句具體方向開始，不擴大戰線。

收束以憑證外觀呈現，點擊「封存並回到現在」時觸發深層物理觸覺震動，將思緒真正鎖定並寫入本機資料庫。使用者永遠可以選擇「還想再說一點」回到原對話。

### 4. 三層時間認知架構（Three-Tier Temporal Cognition Architecture）

系統不採用「所有歷史全部丟進向量資料庫硬撈 Top-K」的傳統 RAG 模式。心智記憶的本質不是「AI 能記住多少」，而是**「不同時間距離的記憶，AI 分別被允許拿來做什麼？」**

系統的核心互動哲學為：
> **「當下陪你停，隔天記得接，時間久了才幫你看見。」**
> **「近的記憶用來承接，遠的記憶用來發現。」**

#### 平行管線（Parallel Pipelines）
新進 Moment 同時流經三條平行管線，彼此獨立評估，**嚴禁實作為 `if-else` 互斥分流**。同一個 Moment 可以既屬於 Continuity（承接昨天未完事件），同時又成為未來 Pattern 的證據點（靜默累積，當下不發言）：

```text
┌→ ① Present Router    ：現在怎麼回應（接住、換角度）
新 Moment ──────────┼→ ② Continuity Router ：是否承接近距事件（免除重述前情提要）
                    └→ ③ Pattern Router    ：靜默累積長期證據（達門檻才浮現）
```

#### 時間認知五大憲法條款

時間回看只在使用者主動進入 REVIEW 時發生。Temporal Delta 只處理已跨越 48 小時的明確狀態確認；Pattern 只在 REVIEW 門檻通過時唯讀呈現原文。

#### 雙軌解耦架構（Dual-Track Architecture）
在 Pattern 檢索與辨識時，系統將思緒解耦為兩條平行軌道：
1. **事件軌道（Event Track）**：同一個人、同一項工作、同一個具體情境（以 `people`、`places`、`activities` 結構化實體區分）。
2. **狀態軌道（State Track）**：封閉的身心狀態家族（如 `LOW_ENERGY`、`HIGH_ACTIVATION`），嚴守純觀察標籤（如 `WITHDRAWN`），嚴禁臨床病理詞彙。

#### 被動鏡映規範（Passive Mirroring Contract）
- **零 AI 解讀**：滿足門檻時，Review 頁僅浮現極淡微文字（如*「這幾件事，好像在碰同一個地方。」*）。點擊後僅並排顯示原始 Moment 原文與時間戳。
- **零輸出字數**：AI 不得產生任何「看得見的變化」、「還可再看的地方」或分析標籤，徹底杜絕說教感，由使用者自行建立認知閉環。未達門檻時 100% 隱形。

### 5. 再散落

回看或收束後，系統不建立待辦、不催促追蹤、不要求結案。下一次回到首頁，使用者仍可從任何一個新的念頭開始。

## 二、分層責任

### 1. 介面層 UI

UI 有五個主要場景：

- `HOME`：留下 Moment。
- `CHAT`：顯示本次 session，提供續談與換角度。
- `LAND`：顯示暫時收束草稿，讓使用者回到現在或繼續說。
- `REVIEW`：以時間流回看 session 與跨時間關係。
- `BACKUP`：顯示本機保存、匯出、匯入與未來同步狀態。

UI 只負責呈現狀態與發出使用者意圖。它不得直接讀寫資料庫、呼叫 Gemini、決定 Moment 關係，或在元件內藏商業規則。回看介面不得要求手動選段、建立群組或為連線命名。

#### 心智庇護所視覺語言與人體工學規範（Sanctuary Design System）
為徹底服務「降低焦慮、提供安全感」的心智本質，介面層全面鎖定以下設計標準，未來所有迭代均須嚴格維持：

1. **和紙暖白與老松墨綠（Wabi-Sabi Palette）**：
   - 底色統一採用自然和紙暖白（`#FAF9F7`），文字採用沉靜黑（`#242826`），主強調色採用老松深綠（`#134230`）。
   - 徹底杜絕電子螢幕常見的冷白刺眼光，營造低刺激、點著微香的和紙茶室空間感。
2. **雙視覺退火切片（Calm Vignettes）**：
   - 首頁常駐兩處自然寫真切片：上方「禪石晨光」（帶綠色呼吸燈 *「現在這一刻，是安靜的」*）與下方「晨霧松林」（*「允許每一種狀態存在，也是給自己的寬容」*）。
   - 當大腦過載、抗拒文字時，以純粹自然光景提供大腦無壓凝視點，降低心理防衛。
3. **44pt 手機無障礙觸控與高對比度**：
   - 全系統所有可點擊按鈕、心情膠囊、視角切換器、底部連結，嚴格遵守 $\ge 44 \times 44\text{pt}$ 拇指觸控人體工學。
   - 文字色彩對比度嚴格遵循 WCAG AA 4.5:1 / AAA 7:1 規範，確保強光或夜間均清晰易讀。
4. **對話流去雜訊與自適應收攏（De-cluttered Stream）**：
   - Chat 畫面全面移除每輪重複的「你剛才說」、「當時的映照」等公文式標籤，改採沉靜對話誌排版。
   - 當對話進入第 2 輪以上時，頂部大標題自動收攏為微型定錨標籤，垂直空間 100% 留給對話。
5. **具溫度的微互動儀式感（Living Micro-interactions）**：
   - 即時字數注入（*「準備傾聽 $\to$ N 字已注入」*）、送出狀態切換（*「留下這句 $\to$ 正在安放…… $\to$ 已安穩停靠」*）。
   - 右上角「定錨 長按」無縫連動全螢幕注水漸層與 ~60 BPM 平靜生理心跳震動，放開即止。

### 2. 流程控制層

`HarborFlowEngine` 是唯一的協調入口。它接收 UI 意圖、執行保存與非同步服務、透過 reducer 更新不可變狀態，再通知 UI 呈現。

`FlowState` 只處理畫面狀態：`HOME`、`CHAT`、`LAND`、`REVIEW`、`BACKUP`；它不能取代資料模型或承擔 AI 判斷。

session 的開始、續談與收束是獨立責任。目前可由 `HarborFlowEngine` 內的 session 方法承擔；當探索對話、重開 session 或多裝置同步增加複雜度時，必須抽成 `HarborSessionEngine`，而不是繼續把規則堆進 UI。

### 3. 核心資料模型

- `Moment`：不可變的使用者原文、時間與輸入意圖。
- `AnchorEvent`：本機保存的輕點或定錨事實；包含時間、類型與長按時長。它不是 Moment，不進入 AI prompt 或跨時間心理推論。
- `HarborSession`：由一個 Moment 開始的一次停靠對話。
- `ConversationTurn`：session 中的使用者或 AI 回合。
- `SessionClosure`：使用者確認後保存的暫時收束；包含其引用的使用者 turn id。
- `ReviewEvidenceSet`：一次使用者主動回看時，由 AI 選出的 Moment id 與日期原文；它只作為當次洞見的可驗證依據，不是資料夾或待辦。
- `TimelineInsight`：以 `ReviewEvidenceSet` 為證據的動態閱讀；可重新生成，不能變成固定診斷。

原文永遠只屬於唯一總時間流。AI 的關聯是回看當下的檢索能力，不是使用者必須維護的 Thread、標籤或群組。

現有 `ThreadLine`、`LinkCandidate`、`LinkDecision` 僅作舊資料相容與遷移用途；新功能不得再新增手動連線 UI。遷移完成前，備份仍必須完整保存它們，不能使舊資料遺失。

### 4. AI 服務層

AI 依任務分角色，而不是由 UI 任意拼 prompt：

- `Present Companion`：回應當前 Moment。在同一次 session 續談時，必須結合本次 session 內的前文對話作為上下文脈絡（理解代名詞與場景指涉），但絕不讀取跨 session 歷史或個人 Profile。要提供貼著原話的新角度或可續談入口。無法可靠生成時，才以引用原句的安全續寫入口降級。

Present Companion 是使用者進入 `CHAT` 後的主要回報，不是過場提示。起始 Moment 在 `CHAT` 開啟後立即請求；同一 session 的後續 Moment 則在保存後立即請求。正常回應以 45–140 個中文字、2–3 句為生成目標；驗證器接受 30–160 字：先準確映照原話，再提出一個能由原文支持的新理解，最後不得提出問題或留下續談入口。它應比單張角度卡完整，但不得把篇幅用在重述、安慰套話或無依據分析。

Present 的結果必須區分三態：通過驗證的 `success` 才能保存為 `immediateReply` 與 assistant turn，並開放 Explore；本地短輸入或純發洩得到的 `acknowledged` 只在當次畫面顯示「已留下。」，不得冒充 AI 分析或寫入對話；網路、Worker、模型或驗證失敗一律為 `unavailable`，顯示重試入口且不保存替代文字。
- `Explore Companion`：只讀取使用者明確打開的當次 session，協助探索、拆開拉扯與換角度；它可以真實陪談，但每一個可能都要區分於事實，不假裝是結論。若呈現角度卡，每張都必須是一段不同、以口語大白話直指感受的 AI 觀點，加上一句可自行回答的延續問題；嚴禁文學比喻、散文修辭與舞台劇式情境描寫。
- `Landing Companion`：只讀取本次 session 的使用者 turn；AI 自己先前的話不能當成收束證據。
- `Memory Retriever`：只有使用者主動要求回看時，才在符合跨日門檻的歷史中尋找可驗證的相關原文；不在剛寫完或對話中自動打斷。
- `Timeline Reader`：只讀取當次 `ReviewEvidenceSet` 的原文，產生附日期的跨時間洞見；它不依賴也不要求使用者建立 ThreadLine。

#### Explore Companion 的三組視角

使用者主動點選「換個角度」時，Explore Companion 要提供的是三段**不同的 AI 內容**，不是四個換句話說的續寫題目。它先只根據本次 session 的使用者原話選擇一組視角；不得讀取跨時間歷史、Profile 或其他 session。每張卡固定包含：一個短標題、一段可回指本次 session 原話的觀點、以及一句可由使用者決定是否回答的延續問題。AI 的文字不能被自動存成使用者的 Moment 或 turn。

一次只能產生**同一批**的三張卡，不可把不同組混在一起。路由結果與其依據是當下、非持久化的 UI 狀態，不是對使用者的標籤。若訊號混合、原文不足，或路由無法提出可驗證的原文依據，必須退回「感受／混亂」預設組。

##### 感受／混亂（預設組）

- **眼前發生什麼（context）**：從當下的抽象感受補足眼前正在發生的具體情境；不追問原因，也不要求回想過去。
- **哪裡不一樣（change）**：對照現在與以前的差異，只讓變化浮現，不替人解釋原因；「以前」只能由使用者在本次對話中定義，不能呼叫 App 歷史記錄。
- **身體怎麼說（body）**：讓人暫時不分析，改從疲累、緊、悶、空等感官接近；它只是可選入口，不能假設身體必有答案或存在症狀。
- **先不下結論（suspend）**：暫時把一句很重的話放旁邊，避免它立刻變成對自己或生活的定論；不能質疑使用者感受的真假。

##### 要做選擇

- **我想守住什麼**：辨認原文中已經說出的價值、底線或不願失去的事；不替使用者指定優先順序。
- **現實卡在哪裡**：區分真正提到的限制、成本或資源，不把猜測補成事實。
- **哪一步還能回頭**：看當下選擇是否存在可逆的小步；不把它變成行動指令或風險建議。
- **放到之後看**：拉開時間距離，看今天急著決定的事在較後面可能還要保留什麼；不預測結果。

##### 與人卡住

- **我在意什麼**：指出使用者親口說出的感受、期待、界線或受影響之處。
- **還不知道什麼**：清楚區分原文已知的對方言行，與尚未知道的對方想法；不能替對方推測恐懼、意圖或防衛。
- **旁觀者會看見什麼**：只根據已說出的互動描述出可觀察的行為，不對任何一方做道德評價。
- **環境正在推什麼**：若原文有具體制度、角色、資源或情境證據，指出其可能影響；若沒有，不能虛構結構原因。

專案管理、時程安排、策略分析或創意發散**不是**第四組。它們會把產品帶往生產力工具與顧問模式，偏離「陪你把卡在心裡的事說清一點，再安心地放下」。工作或專案相關原文仍可使用本功能，但應依真正卡住的地方進入上述三組：工作感受進入感受／混亂、個人取捨進入要做選擇、與同事或主管的互動進入與人卡住。

三張卡的內容與標題都必須彼此不同，且其觀點必須以本次 session 的使用者原話為依據。若資料不足以支撐特定推測，使用「也許／可能／像是」等保留語氣，或退回到不越界的結構性觀點。嚴禁使用文學比喻、散文演繹或舞台劇描寫。點選卡片接續時，UI 只將它的延續問題顯示在輸入區；真正存入對話的永遠是使用者自己寫下的後續文字。

角度卡必須能在手機上一眼掃完：每張觀點以 20–68 個中文字為限、延續問題以 8–32 個中文字為限；不使用開場鋪陳、重述規則或第二段說明。

UI 先顯示 `Present Companion` 的當下回應，不在剛輸入後強制展開視角卡。使用者主動點選「換個角度」後，以單一透鏡呈現最合適的視角，並提供「換下一個角度」進行輪播切換，避免一次攤開多張卡片造成選擇與作業負擔。

每個角色都必須有明確的 prompt 規則與 `Response Validator`。Validator 必須驗證引用是否真的存在、時間門檻是否符合、回覆是否超出長度，以及是否出現診斷、命令、無依據因果或不允許的語言。

每個角色的 prompt、模型設定、輸出 schema 與 validator 必須各自放在 `src/services/ai/roles/` 的獨立檔案。`GeminiProxyClient` 只能做 Worker 通訊、逾時、重試與取得原始回覆；它不得包含任何產品語氣、prompt 或角色判斷。調整一個角色時，不得順帶改變其他角色的規則。

### 5. 保存、備份與同步層

`MindHarborRepository` 是唯一資料入口。Moment、session、turn、closure 與備份中仍需保留的舊版連線資料，都必須經過它，並盡可能採原子寫入。

- `IndexedDB` 是目前的本機真實來源。
- `Migration` 負責把舊版本資料安全升級為目前結構。
- `Backup Export` 匯出完整 JSON，不可只匯出 Moment。
- `Backup Import` 必須先驗證格式再合併，不可覆蓋既有本機資料。
- `Backup Status` 清楚表達本機保存、最後匯出、最後匯入與待備份變更。
- 備份畫面必須列出完整內容清單：Moment、session、turn、closure、AnchorEvent，以及舊版資料中的 line／decision，讓人知道帶走的不只是原始文字。
- 加密雲端同步是未來可選能力，不得破壞 local-first、原文主權與可攜備份原則。
- Local-first 不等於 AI 離線運作：原文與完整資料庫以本機為真實來源；只有使用者觸發 AI 功能時，完成該次任務所需的最小文字才可經 Cloudflare Worker 安全轉送。UI 不得宣稱 AI 使用時「完全不聯網」或「不傳送到任何地方」。

### 6. 後端與安全

`GeminiProxyClient` 處理逾時、重試、正規化與錯誤降級；它不處理 UI 決策。

Cloudflare Worker 只做安全轉送。Gemini API key 只能存在 Worker Secret，不能放入前端原始碼、Vite 環境變數、Git 歷史、備份內容或除錯輸出。

## 三、不可違反的規則

1. 先保存，再顯示「已留下」。
2. UI 不直接呼叫 AI 或 Repository；所有意圖都經過 Flow Engine。
3. AI 不在剛寫完時跳出過去模式；只有使用者主動回看時，才可讀取必要的跨時間原文。
4. AI 回覆不是使用者資料；收束與洞見只能以使用者原文作為事實來源。
5. 洞見必須可回指原文日期與片段；資料不足時應保持安靜。
6. AI 不診斷、不貼人格或情緒標籤、不命令、不替使用者做決定。
7. 跨時間洞見必須至少引用 3 個 Moment、跨 2 個自然日、相隔至少 24 小時；不符合時不得生成洞見。
8. 備份資料必須能完整還原 session、對話、收束，以及所有尚需遷移的舊版連線與決定。
9. 新功能不可把分類、命名、連線或整理責任推回輸入當下的使用者。
10. 跨時間關聯不主動跳出打斷使用者；它只在使用者主動點選回看後，用於產生有證據的閱讀。
11. **Temporal Delta 只記錄使用者當下的明確選擇，不把選擇解讀成永久心理狀態。**

## 四、新功能的開發檢查

新增任何功能前，先回答：

1. 它屬於 UI、Flow、Domain、AI、Data、Infrastructure 或 Quality 的哪一層？
2. 它需要讀取哪些使用者原文？是否取得了當下明確意圖？
3. 它會否改寫原文、改變時間位置、暗示關係或製造待辦壓力？
4. 它的資料如何進入備份、匯入、版本升級與合併？
5. 若 AI 失敗、逾時或沒有可信結果，產品是否仍能安全地保存與離開？
6. 是否有對應的型別檢查、流程測試與 UI 驗證？
